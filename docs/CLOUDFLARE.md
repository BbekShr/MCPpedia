# Hosting: Cloudflare Workers

MCPpedia runs on Cloudflare Workers via [`@opennextjs/cloudflare`][adapter], which
compiles the Next.js 16 App Router build into a single Worker plus a static asset
bundle. This replaces Vercel. Merging `main` still deploys to production — the
trigger is now `.github/workflows/deploy-cloudflare.yml` instead of Vercel's git
integration.

[adapter]: https://opennext.js.org/cloudflare

## Plan requirement

The Worker is **~4.35 MiB gzipped**. Cloudflare's Worker size cap is 3 MiB on the
free plan and 10 MiB on Workers Paid, so **Workers Paid ($5/mo) is required** —
the free plan cannot host this build. Re-measure after any dependency change with:

```
npx opennextjs-cloudflare build
npx wrangler deploy --dry-run --outdir=/tmp/cf-dry   # prints "Total Upload: … / gzip: …"
```

## Moving parts

| Piece | What it does | Where it is configured |
|---|---|---|
| Worker `mcppedia` | Runs the Next server function and `proxy.ts` | `wrangler.jsonc` |
| Static assets | `_next/static`, `public/` — served without waking the Worker | `assets` binding |
| R2 `mcppedia-inc-cache` | ISR payloads for every `export const revalidate = N` page | `NEXT_INC_CACHE_R2_BUCKET` |
| Durable Object `DOQueueHandler` | Time-based revalidation queue (max 50 concurrent regens) | `NEXT_CACHE_DO_QUEUE` |
| D1 `mcppedia-tag-cache` | On-demand `revalidatePath` bookkeeping | `NEXT_TAG_CACHE_D1` |

Overrides are selected in `open-next.config.ts`. If bursty `revalidatePath`
traffic (a wide `compute-scores` run) outgrows D1, switch `tagCache` to
`tag-cache/do-sharded-tag-cache`; the D1 binding then goes unused.

## One-time account setup

Everything below needs a logged-in Cloudflare account and is **not** done by CI.

```bash
npx wrangler login

# 1. ISR payload store
npx wrangler r2 bucket create mcppedia-inc-cache

# 2. Tag cache. Copy the printed database_id into wrangler.jsonc,
#    replacing REPLACE_WITH_D1_DATABASE_ID.
npx wrangler d1 create mcppedia-tag-cache

# 3. Runtime secrets. These are NOT build-time values and are not inlined into
#    the bundle — the Worker reads them per request.
npx wrangler secret put SUPABASE_SERVICE_ROLE_KEY --name mcppedia
npx wrangler secret put REVALIDATE_SECRET        --name mcppedia
npx wrangler secret put MCP_INTERNAL_KEY         --name mcppedia
npx wrangler secret put GITHUB_TOKEN             --name mcppedia   # if used at request time

# 4. First deploy (creates the Worker so WORKER_SELF_REFERENCE resolves)
npx opennextjs-cloudflare deploy
```

### GitHub Actions secrets

`deploy-cloudflare.yml` needs these repository secrets:

- `CLOUDFLARE_API_TOKEN` — token with *Workers Scripts: Edit*, *Workers R2 Storage:
  Edit*, *D1: Edit*, and *Account Settings: Read*
- `CLOUDFLARE_ACCOUNT_ID`
- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_SITE_URL`,
  `NEXT_PUBLIC_CF_ANALYTICS_TOKEN` — inlined into the bundle at build time, so they
  must be present for the *build* step, not just at runtime
- `SUPABASE_SERVICE_ROLE_KEY` — the build prerenders `/s/[slug]`, `/compare/[slugs]`,
  `/skills/[slug]` and the OG images against the real database

### DNS cutover

`mcppedia.org` currently resolves to Vercel. After a deploy has been verified on
the `*.workers.dev` URL:

1. Add `mcppedia.org` (and `www`) as a **custom domain** on the `mcppedia` Worker
   (Workers & Pages → mcppedia → Settings → Domains & Routes).
2. Cloudflare rewrites the DNS records itself if the zone is already on Cloudflare;
   otherwise move the zone to Cloudflare first.
3. Remove the Vercel domain assignment only after traffic is confirmed on the
   Worker, so a rollback is one DNS change rather than a re-add.

Set `NEXT_PUBLIC_SITE_URL=https://mcppedia.org` before the cutover build —
canonical URLs, sitemaps, OG images and JSON-LD all derive from it.

## Deploy vs. upload

Use `opennextjs-cloudflare deploy`, **not** `wrangler deploy`. The adapter's
command also runs `populateCache`, which pushes the build's prerendered output
into R2. Skipping it makes every prerendered route miss — `/blog/<slug>` returns
a hard 404 because that segment is `dynamicParams = false`. This was reproduced
locally, it is not hypothetical.

## Constraints this codebase is written against

- **No filesystem at runtime.** `fs.readFileSync` throws inside a Worker. Blog and
  guide frontmatter is read from `data/blog-index.json` / `data/guides-index.json`,
  generated by `scripts/generate-content-index.mjs` (wired into `prebuild`).
  MDX *bodies* are still read with `fs`, which is safe only because
  `/blog/[slug]`, its `opengraph-image` and `/guides/[slug]` all set
  `dynamicParams = false` and carry no `revalidate` — they never execute in the
  Worker. Adding a request-time `fs` read anywhere will 500 in production and
  pass every local gate.
- **`cf-connecting-ip` is the trusted client IP.** The Cloudflare edge overwrites
  it, so `lib/rate-limit.ts` prefers it. `x-vercel-forwarded-for` is deliberately
  ignored: off Vercel nothing rewrites it, so honouring it would let a caller
  choose their own rate-limit bucket.
- **`maxDuration` is inert.** Workers bill CPU time, not wall clock; the
  `export const maxDuration` values in `app/api/admin/categorize` and `app/mcp`
  no longer gate anything. The Vercel-ceiling failure mode they guarded against
  (a value above the Hobby cap failing the build) is gone with them.
- **The Edge runtime is unsupported** — every route must stay on the Node runtime.

## Known noise

`opennextjs-cloudflare build` logs `ERROR Failed to copy …` for ~40 unified/mdast
packages. The adapter only copies packages listed in `serverExternalPackages`,
which this project does not set, so the copy would have been a no-op either way;
the message comes from an over-broad `catch` in the adapter. Harmless.
